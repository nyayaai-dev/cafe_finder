In one sentence: a static website (HTML, CSS and plain JavaScript, no framework) draws an OpenStreetMap-style map with Leaflet; all the data is prepared ahead of time by Python build scripts that download OpenStreetMap, clean it and merge in ratings from listing sites; it is hosted free on GitHub Pages, refreshed monthly by a GitHub Action, and installs on phones as a Progressive Web App. An optional serverless Python function adds live Google details if a key is configured.

1Summary — what the app is

A map-and-list finder for every named cafe and restaurant across Greater Mumbai, Thane and Navi Mumbai. Each place shows its area, category, cuisine, pure veg / Jain / non-veg labels, rating and cost for two (where a listing gives them), opening hours with an “Open now” badge, menu links (Zomato, Swiggy), directions, and the nearest train / metro / monorail station with walking or auto time.

Main features

Finding places

  • Smart search: “bandra pizza”, “jain kala ghoda”, “cafes near station in thane”, or a place name
  • 1,033+ named areas, localities and stations; quick area chips
  • Filters: cafes / restaurants, cuisine, pure veg, Jain, non-veg, has rating, open now, near a station, saved
  • Mood chips: work-friendly, date night, under ₹500, late night, breakfast, desserts
  • Sort by distance, rating, cost, name or detail
  • Near me (GPS) with walking times; Surprise me; heatmap

Using results

  • Detail panel: weekly hours, nearby places within 500 m, stations, links
  • Save favourites (♥), share a place or a whole saved list by link
  • Compare up to 3 places side by side
  • Filters kept in the address, so any view can be shared
  • Report a problem / suggest a place (pre-filled GitHub issue)
  • Resizable list and map on computers; bottom sheet on phones

App and offline

  • Installable app (PWA) with its own install page and QR code
  • Works offline after the first visit; updates itself on the next open
  • Dark mode follows the phone’s setting

For search engines

  • 137 area pages and 292 food guides (e.g. “Pizza in Bandra”)
  • Sitemap, robots.txt, link-preview image, structured data (schema.org)
  • Privacy page and custom 404 page

4Architecture

The app has no always-on server and no database. All the heavy work happens before anyone visits: Python scripts turn raw OpenStreetMap data into compact files, and the browser does the rest.

Request flow when someone opens the site

  1. The browser downloads index.html (≈ 37 KB compressed), then data/places.js (≈ 100 KB) and data/basemap.js (≈ 480 KB), plus Leaflet from cdnjs.
  2. The page draws land, water, parks, roads and rail from the vector data on a canvas, then places 2,626 pins in clusters.
  3. Everything after that — search, filters, sorting, distances, opening hours, nearest stations — is computed in the browser, instantly, with no further network calls.
  4. Zooming in past street level loads data/streets.json once and draws only the grid cells in view.
  5. The service worker stores these files so the next visit (or the installed app) works offline, and checks the server for a newer version each time.

5Frontend (what runs in the browser)

Structure

The app is one HTML page assembled at build time from build/template.html (markup, base styles, the main script) plus build/parts/features.js and features.css (later features). The JavaScript is a single immediately-invoked function, so nothing leaks into global scope. There is no framework and no client-side build step.

6Backend (build pipeline, API, automation)

“Backend” here means three things: the build pipeline that prepares all data ahead of time, an optional serverless function for live Google details, and GitHub Actions automation. There is deliberately no database: the data is read-only for visitors and fits in a few megabytes, so shipping it as static files is faster, cheaper and works offline.

6.2 Live Google details — api/place.py (optional)

  • A Vercel Python serverless function: GET /api/place?name=…&lat=…&lng=… → rating, review count, price level / range, serves-vegetarian, open now, Google Maps link.
  • One Google Places API (New) Text Search per lookup, biased to 300 m around the place; picks the closest match within 400 m; answers only for the covered region.
  • The key lives only in the server’s GOOGLE_MAPS_API_KEY environment variable; responses are cached at the edge for a day. Google data is shown live and never stored, as Google’s terms require.
  • ?probe=1 lets the page check whether a key is configured. On GitHub Pages there is no server, so the probe fails and the feature stays hidden.

6.3 Automation — GitHub Actions

.github/workflows/refresh-data.yml runs at 08:00 IST on the 1st of every month (and on demand): sets up Python, downloads places, rebuilds the site, commits if anything changed, and republishes the gh-pages branch.

6.4 Local development

dev_server.py serves site/ on port 8780 and runs /api/place the same way Vercel would, reading the key from a git-ignored .env file.

7Data: sources, model and formats

Sources

NominatimCoordinates for listing-site places and areasPublic geocoder, cached locally

Place record (one row per place in data/places.js)

[ name, isRestaurant, kind, address, lat, lng, "cuisine;list", hours, phone, website, menu,
  source, sourceUrl, costForTwo, suburbIndex, localityIndex, areaIndex,
  rating, ratingSource, costSource, dietBits, isWebListing ]

dietBits: 1 = pure veg, 2 = Jain food, 4 = non-veg, 8 = has veg options

Other formats

  • Map geometry: coordinates multiplied by 100,000 (≈ 1 m) and stored as differences from the previous point — small integers that compress well.
  • Stations: [name, 0 train | 1 metro | 2 monorail, lat, lng, "Line;Line"].
  • Place key: djb2 hash of name|lat|lng (4 decimals) in base 36 — identical in JavaScript and Python, so links stay stable across rebuilds.
  • Opening hours: OpenStreetMap syntax (e.g. Mo-Fr 08:00-23:00; Sa,Su 09:00-01:00) parsed in the browser.

8Key algorithms

ProblemApproach
Covered regionRay-casting point-in-polygon test against an 11-point outline (Mira Road – Kalyan – Panvel – Colaba).
Naming every areaEach place takes its nearest named locality, neighbourhood and main area (nearest-centre assignment), so even small spots like Charni Road get a name.
Drawing the coastCoastline ways are chained end to end, clipped to the view box and closed along its edge to form land polygons; water and parks are layered on top.
Small map filesDouglas–Peucker style simplification per layer, then delta-encoding; residential streets split into grid cells and loaded only when zoomed in.
Matching listings to mapNormalised names (brackets, “restaurant”, punctuation removed) must match or contain each other, within 2.2 km of the geocoded area; closest wins.
DuplicatesSame name key (accents and case removed) within 150 m → merged, keeping the richer record and filling gaps from the other.
Veg / Jain labelsName and cuisine rules (Udupi, thali, sweets, juice, Shiv Sagar, Rajdhani…) — never applied if anything suggests meat (seafood, biryani, kebab, bar, Irani).
DistancesHaversine great-circle distance; streets assumed 1.3× straight line.
Travel timeUp to 2 km: walking at 4.8 km/h. Beyond: auto / taxi at about 18 km/h plus 3 minutes.
Station linesA station gets every local / metro route whose track passes within 150 m of it.
Open nowHours parsed into minute ranges per weekday, including spans past midnight; current time taken in Asia/Kolkata.
Smart searchLongest area name first; keyword rules before cuisines; leftover words become a name filter; an exact name opens the place, a chain name lists all branches.

9Hosting, deployment and updates

  • Source: GitHub repository nyayaai-dev/cafe_finder, branch main.
  • Published site: the site/ folder is split into the gh-pages branch (git subtree split --prefix site) and served by GitHub Pages over HTTPS.
  • Updates reach visitors: the service worker checks the page and data with the server on every visit (“no-cache”), falls back to its copy offline, and reloads once if a new version takes over right after opening.
  • Alternative host: vercel.json serves site/ with security headers and enables the Google function.
  • claude.ai version: build.py --single inlines everything into one HTML file for the shareable artifact.

Publishing commands

py build/build.py
git add -A && git commit -m "Update site"
git push origin main
git subtree split --prefix site -b gh-pages-new
git push -f origin gh-pages-new:gh-pages && git branch -D gh-pages-new

10Security and privacy

  • No accounts, no ads, no tracking cookies. Visitor counting (GoatCounter) is optional and cookie-free.
  • Saved places and list width stay in the browser’s localStorage; GPS position is used only on the device.
  • All text from data is HTML-escaped before display; the Google key never reaches the browser.
  • On Vercel: Content-Security-Policy, HSTS, no framing, no-sniff, strict referrer and permissions policies.
  • External scripts only from cdnjs with exact versions; fonts only from Google Fonts.
  • Reports and suggestions go through GitHub issues, so nothing personal is collected by the site.

12Rebuilding it from scratch

Needs only Python 3.12+ and Git (no packages to install).

git clone https://github.com/nyayaai-dev/cafe_finder.git
cd cafe_finder

# 1. Download the data (OpenStreetMap; takes 10–30 minutes)
py build/fetch_places.py        # cafes and restaurants
py build/fetch_region.py        # localities and stations
py build/fetch_geo.py           # area outlines and groups
py build/fetch_detail.py        # coastline, roads, rail, parks (into build/raw/)
py build/process_map.py         # compact base map
py build/fetch_transit.py       # train, metro and monorail stations
py build/resolve_hotspots.py cache   # match listing-site ratings (edit build/hotspots.py first)

# 2. Build and run
py build/build.py               # writes site/
py dev_server.py                # open http://127.0.0.1:8780

# 3. Publish (GitHub Pages)
git add -A && git commit -m "Update"
git push origin main
git subtree split --prefix site -b gh-pages-new
git push -f origin gh-pages-new:gh-pages && git branch -D gh-pages-new

Optional: set GOOGLE_MAPS_API_KEY and deploy to Vercel for live Google details; add a GoatCounter code in build/config.json for visitor stats; run build/make_og.ps1 on Windows to redraw the preview image.

13Limitations and next steps

Known limitations

  • Ratings and cost for two cover about 250 popular places; the rest link to Google for ratings. Some listing ratings rest on few reviews.
  • 228 places from listing sites have approximate pins (area centre); Directions finds the exact spot by name.
  • Veg / Jain labels are rule-based where the data is silent; mood chips are best guesses.
  • Travel times are estimates (straight-line × 1.3, typical speeds), not live routing; bus stops are not included.
  • No user reviews or photos yet; per-place link previews show the site card.

Next steps

  1. Real-world testing with a handful of users; fix what they stumble on.
  2. Google Search Console + sitemap; GoatCounter for visitor stats.
  3. Google key on Vercel for live ratings and photos on every place.
  4. Ratings for remaining areas (Dadar, BKC, Thane, Mira Road, Kalyan, Panvel).
  5. Custom domain; later, user reviews with moderation; Hindi / Marathi interface.
