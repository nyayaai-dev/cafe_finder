# Mumbai Cafe & Restaurant Finder

Every named cafe and restaurant from Colaba to Mira Road, Thane, Bhiwandi,
Kalyan–Dombivli, and Navi Mumbai to Panvel, on an OpenStreetMap-style map.

- Search 900+ areas, localities and stations (Charni Road, Kala Ghoda, Vashi…)
- Cafés and restaurants, cuisine, pure veg / Jain / non-veg filters
- Ratings and cost for two from current listings for the hotspots, plus live
  Google rating, price and veg info when you open a place (needs a Google key)
- Directions, Zomato and Swiggy menu links, and Near me on the live site
- ♥ Save favourites (kept in your browser), Share a link to any place (`#p-…` opens it)
- Open now filter, read from each place's opening hours (Mumbai time)
- Suggest a missing place (opens a pre-filled GitHub issue)
- Install it as a phone app; it works offline after the first visit
- Data refreshes itself on the 1st of every month (GitHub Action)
- Phone-first layout: full-screen map with a draggable bottom sheet
- Place detail panel with weekly hours, nearby places and Compare (up to 3)
- Smart search ("Bandra pizza", "Jain Kala Ghoda", a café name) with suggestions
- Mood chips (Work-friendly, Date night, Under ₹500, Late night, Breakfast, Desserts),
  Surprise me, heatmap, top picks, walking times with Near me, shareable saved lists
- Area pages for search engines (`site/areas/`), sitemap, link-preview image (`site/og.png`)
- Food guides by cuisine and area (`site/food/`, e.g. Pizza in Bandra, Jain food), linked from area pages
- Filters live in the address, so any view can be shared (`?area=Bandra&cat=cafe&f=veg,open&cuisine=Pizza&mood=date&sort=rating`)
- Report a problem on any place (pre-filled GitHub issue, label `data fix`)
- Privacy page, custom 404 page, offline notice and loading placeholders

## How it's built

| Folder | What's in it |
| --- | --- |
| `site/` | The website Vercel serves. Generated by `build/build.py`, committed so deploys need no build step. |
| `api/place.py` | Vercel Python function: looks one place up on Google Places when its popup opens. Keeps the key on the server. |
| `build/` | Scripts that download OpenStreetMap data, draw the base map and build `site/`. |
| `data/` | Inputs and generated data: places snapshot, localities, base map, hotspot listings. |
| `dev_server.py` | Runs `site/` + `/api/place` locally, the same way Vercel does. |
| `legacy/` | The first prototype (tile-crawling server and UI), kept for reference. |

## Run locally

```
py build/build.py
py dev_server.py
```

Open http://127.0.0.1:8780.

## Deploy (GitHub + Vercel)

1. Push this folder to a GitHub repository.
2. On vercel.com: **Add New → Project → Import** the repository. Keep the defaults (`vercel.json` sets everything).
3. For live Google details: **Settings → Environment Variables**, add `GOOGLE_MAPS_API_KEY`, then redeploy.

Every push to `main` redeploys the site.

### Google key safety and cost

- In Google Cloud, restrict the key to **Places API (New)** and set a **daily quota** and a **budget alert**.
  `/api/place` is public, so the quota is what caps spending if someone hammers it.
- Each popup opened is one Text Search call. Answers are cached at Vercel's edge for a day,
  so repeat opens are free.
- Google's terms allow showing its data live; the site never stores it.

## Publish to GitHub Pages

The live site is the `gh-pages` branch, made from the `site/` folder:

```
py build/build.py
git add -A && git commit -m "Update site"
git push origin main
git subtree split --prefix site -b gh-pages-new && git push origin gh-pages-new:gh-pages && git branch -D gh-pages-new
```

### Your own domain

1. Buy a domain (for example from GoDaddy, Namecheap or Google Domains' successor).
2. In the repo: **Settings → Pages → Custom domain**, enter it (e.g. `cafes.example.in`) and save.
3. At the domain seller, add a `CNAME` record pointing `cafes` to `nyayaai-dev.github.io`
   (for a bare domain, add `A` records to 185.199.108.153, .109.153, .110.153 and .111.153).
4. Back in Pages settings, tick **Enforce HTTPS** once it's offered.

## Automatic monthly refresh

`.github/workflows/refresh-data.yml` runs on the 1st of each month (and from the
Actions tab with **Run workflow**). It downloads places, rebuilds, and republishes
Pages. If a download looks cut short (under 90% of the current places), it stops
without changing anything.

## Refresh the data by hand

```
py build/fetch_places.py       # cafes and restaurants from OpenStreetMap
py build/fetch_region.py       # localities and stations
py build/fetch_detail.py       # detailed map layers (into build/raw/)
py build/process_map.py        # base map
py build/resolve_hotspots.py   # match hotspot listings (edit build/hotspots.py first)
py build/build.py              # rebuild site/
```

The single-file version used for the claude.ai shareable link is built with
`py build/build.py --single page.html`.
